# Codex 额度调度器 · 管理界面 UI 设计交接文档

> 版本基线：v0.4.0（v4 界面）。本文档面向 UI 设计团队，完整列出前端需要展示的
> 全部内容、数据、状态与交互行为。样式可以完全重新设计；信息架构与数据契约
> 以本文档为准。

---

## 一、项目介绍

**Codex 额度调度器**（codex-quota-scheduler）是 CLIProxyAPI（CPA，一个 AI
网关）的动态库插件。CPA 管理多个 OpenAI Codex 账号（OAuth 凭证），本插件
接管"每次请求用哪个账号"的决策：按**真实额度可用性**（而非固定顺序）选择
账号，额度耗尽的账号自动避让、窗口重置后自动恢复。

**使用者**：自建 CPA 的个人/小团队运维者，手上有几个到几十个 Codex 账号
（Plus/Team/Pro），希望把额度榨干、避免 429。

**核心概念**：
- **5 小时额度 / 周额度（或月额度）**：每个 Codex 账号有两层额度窗口，各自
  有已用百分比和重置时间。任一窗口耗尽则账号不可用，直到该窗口重置。
- **CPA 优先级**：宿主侧的账号权重（数字越大越优先），插件在其之上叠加
  自己的调度。
- **插件优先级 999**：置顶（pin）。用户可把某账号钉在调度队列最前。
- **响应观测**：真实请求的响应流里携带额度帧，插件借此更新缓存，可推迟
  轮询。
- **模型重试链**：上游对某模型返回 429/502/503/容量不足时，按配置的备用
  模型链自动改写请求重试（有影子模式，只记录不重试）。

**本界面**：插件内嵌的单页管理界面（无框架、原生 HTML/CSS/JS，嵌在 Go
二进制里），由 CPA 管理中心以 iframe 方式打开，也可直接访问。双语
（简体中文 / English）。

## 二、整体布局与全局要素

### 2.1 骨架

```
┌──────────┬──────────────────────────────────────┐
│  侧栏     │  主区（一次只显示一个页面）             │
│  品牌     │  ┌ toast 通知（顶部，数秒后淡出）────┐  │
│  导航×4   │  └───────────────────────────────┘  │
│  ──────  │  [页面内容]                           │
│  连接区   │                                      │
└──────────┴──────────────────────────────────────┘
```

- **侧栏·品牌区**：产品名 + 一句话副标题。
- **侧栏·导航**（4 项，当前项高亮，支持 aria-current）：
  1. 账号总览（默认页）2. 日志 3. 调度设置 4. 模型重试链
- **侧栏·连接区**（分隔线下方）：
  - 界面语言切换（中文/English）
  - CPA 管理密钥输入（password 框）+「在此浏览器中记住管理密钥」开关
    （帮助文案：密钥明文存于浏览器本地存储，仅受信任设备启用）
  - 「加载数据」按钮（未加载时）/「刷新额度」按钮（已加载后）
  - 静态提示条：调度器后台自动运行，无需保持页面开启
- **主区**：hash 路由（`#overview / #logs / #settings / #retry`），刷新保持
  当前页，页面可收藏。

### 2.2 全局浮层与提示

| 要素 | 触发 | 行为 |
|---|---|---|
| toast 通知 | 任何操作结果（成功/失败） | 主区顶部出现，成功 4.5s、失败 8s 后淡出；红色/绿色语义 |
| roster 生命周期警告条 | 宿主无法确认账号列表时 | 主区顶部黄色警告条，含标题+正文 |
| 重置探测警告条 | 设置页内，探测开关关闭且已加载时 | 黄色警告，说明开启后果 |

### 2.3 双语

所有文案有 zh-CN / en 两套（en 文本普遍长 20–40%，设计需容纳）。跟随
CPA 管理中心语言，也可手动切换并记住。时间显示为浏览器本地时区。

## 三、P1 账号总览（默认页）

### 3.1 页头指标条（3 个指标）

| 指标 | 含义 | 值示例 |
|---|---|---|
| 下一账号 | 下一次 Codex 请求会选的账号 | `main-team` / 暂无 |
| Monthly 模式 | 月度账号使用方式 | 按到期时间 / 优先使用 |
| 最近选择 | 上次实际选中的账号 | `backup-2` / 暂无 |

### 3.2 账号卡片（核心组件）

按调度顺序排列的卡片网格（2–4 列自适应）。**每张卡片的数据全集**：

**① 标题行**
| 字段 | 说明 | 示例/形态 |
|---|---|---|
| 显示名 | 别名优先，无别名用 auth ID | `主力账号` |
| auth ID | 技术标识，等宽字体 | `auth:main-team` |
| 分组 | 账号所属分组 pill | `运营组` |
| 标签 | 自由标签 0–n 个 | `team` `paid` |
| 队列序号 rank | 调度顺序 | `#1` |
| CPA 优先级 | 宿主侧权重 | `5` |
| 插件优先级 | 999=置顶 | `0` / `📌 999` |

**② 状态徽章行**（按存在与否条件显示）
| 徽章 | 形态 |
|---|---|
| 下一优先 | 高亮色（该卡片同时整卡描边高亮） |
| 可用 | 绿色 |
| 不可用原因 | 红色，**内联恢复时间**（如「额度已耗尽 · 恢复还需 2小时」）。原因枚举见 §8.2 |
| 账号类型 | weekly / monthly / 未知 |
| 熔断状态 | `熔断：全开` / `熔断：等待中` / `熔断：半开` |
| 请重新登录 | 红色（登录失效） |
| 刷新到期原因 | 如「刷新间隔已到」「上次刷新失败」 |

**③ 额度条**（两行，5 小时窗口 + 长窗口）
每行：窗口名 | 已用/剩余百分比 | 距重置剩余时间（`剩3小时` / `剩2天`）|
进度条（按剩余量着色：>60% 绿、30–60% 琥珀、<30%/耗尽 红；窗口缺失时显示
「暂无数据」灰色条）。绝对重置时间可放 hover tooltip。

**④ 元信息行**（小字流式）
缓存时间（`2分钟前`）· 额度来源（响应观测/轮询刷新）· 主动重置次数
（`2 次 / 累计 5 次`）+ 条件项：托管停用状态、调度状态说明、最后错误、
下次重试时间。

**⑤ 备注**（条件）：账号备注、分组备注文本块。

**⑥ 操作按钮**：`📌 固定/📌 取消固定`｜`刷新额度`（单账号）｜`编辑`。

**卡片整体状态**：置顶卡（蓝框高亮）、下一优先卡（描边）、不可用卡（可降透明度）。

### 3.3 空态

无账号数据：「暂无账号数据。等待额度刷新后，这里会显示账号卡片。」

## 四、P2 日志

**筛选芯片行**：`全部 N`｜`ℹ info N`｜`⚠ warn N`｜`✕ error N`（带计数，
点击过滤，当前项高亮）。

**操作**：刷新日志、导出日志（下载 JSON）。

**日志列表**（倒序，最多 80 条）：每条含
- 时间（本地时区）
- 等级（info 蓝 / warn 琥珀 / error 红，左边框或色点）
- 事件名（技术 ID，等宽，如 `quota.refresh_success`）
- 消息（跟随界面语言）
- 字段键值对（如 `auth_id=main-team, error=401`）

空态：「暂无日志。发起请求或手动刷新额度后，这里会显示记录。」

## 五、P3 调度设置

页头说明条：默认配置已经过优化，正常情况下无需手动调整；修改后记得保存。
底部操作行（右对齐）：导出配置｜导入配置｜**保存设置**（主按钮）。

字段按五组卡片组织。**每组有标题 + 一句组级说明；每项有名称 + 帮助文案**
（以下帮助文案即产品定稿文案）：

### 组 1 ⚙ 常规（组说明：决定调度器何时接管请求，以及账号之间如何排序）
| 字段 | 类型 | 默认 | 帮助文案 |
|---|---|---|---|
| 启用调度接管 | 开关 | 开 | 开启后，每次 Codex 请求由本插件按额度可用性选择账号；关闭则完全交回 CPA 内置调度 |
| 更高优先级耗尽时使用较低优先级账号 | 开关 | 开 | 开启后，所有 CPA 优先级层级的账号都会纳入调度；更高层级只要还有可用账号就一定优先，仅在更高层级全部不可用时才会选用低层级。关闭则保持只调度最高优先级层 |
| 月度账号使用方式 | 单选 | 按到期时间排序 | 月度（Monthly）账号的额度按月重置。「按到期时间排序」先用重置时间最早的月度账号，避免月底额度浪费；「优先使用月度账号」总是先用完月度账号，再动周额度账号 |

### 组 2 🔄 额度刷新（组说明：控制插件多久向 Codex 查询一次各账号的额度，以及缓存何时算过期）
| 字段 | 类型 | 默认 | 帮助文案 |
|---|---|---|---|
| 额度刷新间隔 | 数字+单位(分/时/天) | 30 分钟 | 每隔多久查询一次全部账号的额度。真实请求返回的额度信息会自动推迟下一轮查询 |
| 缓存过期判定 | 数字+单位 | 5 小时 | 超过此时长没有额度数据的账号视为「过期」，优先安排刷新 |
| 活跃刷新窗口 | 数字+单位 | 1 小时 | 最近这段时间内有过 Codex 请求时按刷新间隔执行；空闲后降频，节省额度与请求 |
| 重置后刷新延迟 | 数字+单位 | 1 分钟 | 额度窗口的重置时间点过后，等多久再查询，给上游留出生成新窗口的时间 |
| 认证失败重试间隔 | 数字+单位 | 30 分钟 | 登录失效（401）的账号按此间隔低频重试，避免频繁撞无效凭证 |
| 刷新失败重试间隔 | 文本（逗号分隔序列） | 1m,5m,15m | 额度查询失败后的重试间隔序列（逗号分隔）；全部用完后等待下一个刷新周期 |
| 启动时刷新额度 | 开关 | 关 | CPA 启动时立即刷新一轮额度；关闭则等首个请求触发 |
| 最大并发刷新 | 数字 | 1 | 同时查询额度的最大账号数。账号很多时可适当调大，但过高可能触发上游限流 |

### 组 3 ⚠ 失败与恢复（警示样式；组说明：账号出错或额度耗尽后的自动处理。⚠ 标记的选项有副作用，改动前请读说明）
| 字段 | 类型 | 默认 | 帮助文案 |
|---|---|---|---|
| 失败反馈标记额度耗尽 | 开关 | 开 | 上游确认额度耗尽（usage_limit_reached）时立即把账号标记为不可用，直到窗口重置。关闭后只能靠定时刷新发现耗尽，调度会多撞几次 429 |
| 自动激活新的额度周期 ⚠ | 开关 | 关 | 额度重置时间已到但新窗口迟迟未生成时，发送一次极小的 Codex 请求尝试「激活」新周期。其余时间只做只读检查；可能消耗少量额度 |
| 账号列表未确认时仍允许额度探测 ⚠ | 开关 | 关 | CPA 暂时无法确认当前账号及优先级时，允许插件用最近保存的账号列表执行上面的探测。每次都会重新验证凭据，但无法保证账号未被删除或调整。通常应保持关闭 |
| 额度耗尽时在 CPA 层停用账号并自动恢复 ⚠ | 开关 | 关 | 确认额度耗尽时把该账号的 CPA 凭据标记为 disabled，之后按刷新间隔只读检查，两个额度窗口都可用时才自动恢复。人工手动停用的账号绝不会被改动。开启后插件会写宿主的认证文件 |

组脚注：⚠ 后两项为高风险操作（额度探测使用过期账号列表、写宿主认证文件），
保持默认关闭，除非明确需要。

### 组 4 🔒 熔断器（组说明：账号连续失败后临时停用一段时间，避免持续向故障账号发请求）
| 字段 | 类型 | 默认 | 帮助文案 |
|---|---|---|---|
| 熔断失败阈值 | 数字 | 5 | 连续失败达到该次数后进入熔断，暂时不再选择该账号 |
| 熔断等待时间 | 数字+单位 | 30 分钟 | 熔断后等待多久，才允许半开试探 |
| 半开恢复成功次数 | 数字 | 2 | 半开试探期成功该次数后，账号完全恢复参与调度 |

### 组 5 📊 日志与历史（组说明：插件日志与托管停用历史的容量上限，超出后丢弃最旧记录）
| 字段 | 类型 | 默认 | 帮助文案 |
|---|---|---|---|
| 最大日志条数 | 数字 | 200 | 面板与导出中保留的最大日志条数 |
| 日志保留时间 | 数字+单位 | 24 小时 | 日志的最长保留时间，超期的记录在刷新时清理 |
| 托管停用历史条数上限 | 数字 | 50 | 「CPA 层停用并自动恢复」的历史最多记录条数，用于排查自动停用原因 |

**数字+单位输入**：数值框 + 单位下拉（分钟/小时/天/原始）组合；「原始」为
无法拆解的 Go duration 兜底显示。

## 六、P4 模型重试链

### 6.1 运行模式（四选一分段选择器）
`关闭`｜`影子`｜`生效`｜`全局`
说明文案：影子=只记录会重试的情况，不真正重试（灰度观察）· 生效=仅链内
模型重试 · 全局=所有模型都重试。四选一，替代原来的三个开关。

### 6.2 重试链编辑器
- 每行：**客户端请求的模型** → 备用目标序列（每项=提供方(可空)+模型名），
  可增删、可排序
- 帮助文案：左列是客户端请求的模型；右侧按顺序填备用目标。提供方留空时由
  CPA 自动选择，填写时使用 CPA 的提供方键（如 codex、openai）。只对出现在
  这里的模型生效（全局模式除外）
- 「添加模型」「载入模型列表」按钮；模型列表从 CPA 动态获取（提供方+模型
  建议列表）
- 空态：暂未配置重试链，添加一个模型开始

### 6.3 CPA 前置检查（独立卡片）
状态行（✓ CPA 版本与四项前置配置全部正确 / ✗ 需要升级 CPA / 差异摘要）
+「检查并修复」按钮。点击修复时弹出**确认块**：当前值 vs 推荐值对照表
（request-retry / buffering / timeout / bootstrap-retries 四项，差异项标红），
「应用推荐设置」/「取消」。

### 6.4 高级参数（默认折叠）
折叠头显示摘要：`最大尝试 4 · 静默 60s · 等待 90s · 整链 240s · 帧 4096 · 字节 8MB · 移除加密推理 ✓`
展开后 7 项：最大尝试次数(1–16)、保留帧上限、单次静默超时、等待可提交内容
上限、整条链总时限、保留字节上限、切换模型时移除加密推理内容（开关，帮助：
Codex 加密推理由原模型签名，换模型后无法验证，保留开启避免上游拒绝）。

### 6.5 运行记录
统计卡 6 个：模式｜请求数｜重试次数｜重试后成功（绿）｜重试后失败（红）｜
本应重试(影子)。下方最近重试事件列表（时间+事件+字段），「刷新记录」按钮。

### 6.6 保存
独立「保存重试链设置」按钮（与设置页保存互相隔离——重试页保存不会提交
设置页的未保存改动）。校验失败（空链+启用、数值越界、时长格式错）以
toast/内联提示。

## 九、交互行为要求（样式可变，行为需保留）

1. hash 路由四页，刷新保持，未知锚点回落总览
2. toast 自动淡出（成功 4.5s / 失败 8s）
3. 数字+单位输入与 Go duration 互转；「原始」兜底
4. 设置页/重试页保存隔离；表单 dirty 时刷新不覆盖用户输入
5. 受保护操作需管理密钥；「记住密钥」可恢复
6. 置顶（pin/unpin）即时生效并重排卡片
7. 时间一律本地时区；双语完整覆盖（含徽章、单位、空态）
8. 响应式：窄屏（<860px）侧栏折叠为顶部横条

## 十、技术约束（设计交付时注意）

- 单文件内嵌：整个页面是 Go 二进制里的一个 HTML（无外部资源、无字体/
